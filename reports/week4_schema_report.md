# Week 4 Report — Data Storage Schema and Feature Engineering

## Objective

The objective of Week 4 was to design a simple analytical storage structure and create transformed features for sales forecasting and dashboarding.

This phase connects the cleaned dataset from the ETL pipeline with the modeling and visualization phases.

---

## Input Dataset

Input file:

```text
data/processed/rossmann_cleaned.csv
```

This file is generated by running:

```bash
python pipeline/run_pipeline.py
```

The cleaned dataset contains merged sales and store-level data.

---

## Storage Design

A simple star schema was designed for analytical storage.

```text
                 dim_store
                    |
dim_date ---- fact_sales ---- dim_promo
```

---

## Fact Table

### `fact_sales`

This table contains measurable daily sales data.

| Column | Description |
|---|---|
| Store | Store identifier |
| Date | Sales date |
| Sales | Daily sales value |
| Customers | Number of customers |
| Open | Whether the store was open |
| Promo | Whether promotion was active |
| StateHoliday | State holiday information |
| SchoolHoliday | School holiday indicator |

---

## Dimension Tables

### `dim_store`

Contains store-level attributes.

| Column | Description |
|---|---|
| Store | Store identifier |
| StoreType | Type of store |
| Assortment | Product assortment type |
| CompetitionDistance | Distance to nearest competitor |
| Promo2 | Whether store participates in continuous promotion |

### `dim_date`

Contains date-related attributes.

| Column | Description |
|---|---|
| Date | Calendar date |
| Year | Year |
| Month | Month |
| Week | Week number |
| DayOfWeek | Day of week |
| IsWeekend | Weekend indicator |

### `dim_promo`

Contains promotion and holiday-related attributes.

| Column | Description |
|---|---|
| Promo | Promotion flag |
| Promo2 | Continuous promotion flag |
| StateHoliday | State holiday |
| SchoolHoliday | School holiday |

---

## Feature Engineering

Feature engineering was performed to make the dataset suitable for forecasting.

### Date Features

- Year
- Month
- Week
- DayOfWeek
- Quarter
- IsWeekend

### Lag Features

- Sales_Lag7
- Sales_Lag14
- Sales_Lag30

Lag features help the model understand previous sales patterns.

### Moving Average Features

- Sales_MA7
- Sales_MA30

Moving averages help capture short-term and medium-term sales trends.

### Store-Level Aggregation Features

- Store_AvgSales
- Store_StdSales
- Store_MedianSales

These features help the model understand each store’s historical performance.

### Promotion and Interaction Features

- Promo
- Promo2
- Promo_Weekend

These features help measure promotion impact and interaction with weekend sales behavior.

---

## Optimization Strategies

The following optimization ideas were documented:

| Optimization | Purpose |
|---|---|
| Star schema | Improves analytical clarity |
| Date-based fields | Supports time-series filtering |
| Store-level aggregations | Improves repeated analysis |
| Moving averages | Improves forecasting quality |
| Indexed keys such as Store and Date | Improves query filtering performance |
| Pre-aggregated summaries | Helps dashboards load faster |
